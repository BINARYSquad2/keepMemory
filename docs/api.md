# REST API

Полная машиночитаемая спецификация находится в [contract.json](contract.json) (OpenAPI 3.1). Локальный backend по умолчанию доступен на `http://localhost:8080`.

## Авторизация

`POST /api/auth/register` и `POST /api/auth/login` публичны. API записи и профиля требуют заголовок:

```http
Authorization: Bearer <JWT>
```

Токен подписывается HS256 и действует 7 дней. Подписанные ссылки медиа авторизуют только чтение конкретного файла конкретного владельца и действуют 24 часа. Текущий API не имеет маршрута для серверного logout или обновления токена; клиентский выход удаляет токен с устройства. Ошибки API возвращаются в формате `{"error":"..."}`.

## Системные маршруты

### `GET /health`

Проверяет доступность процесса (liveness).

```json
{
  "app": "KeepMemory",
  "status": "ok",
  "aiEnabled": false
}
```

### `GET /health/ready`

Проверяет соединение с PostgreSQL и доступность каталога `UPLOADS_DIR` на запись. При временной недоступности возвращает `503`; этот путь рекомендуется указать в health check Railway.

## Аккаунты

### `POST /api/auth/register`

Запрос:

```json
{
  "name": "Имя",
  "email": "name@example.com",
  "password": "минимум-8-символов"
}
```

Успешный ответ — `201 Created` с `token`, `tokenType: "Bearer"` и `user`. Повторный email возвращает `409 Conflict`. Сервер нормализует email к нижнему регистру и хеширует пароль bcrypt. Минимальная длина пароля проверяется backend в байтах и составляет 8.

### `POST /api/auth/login`

Принимает `email` и `password`. Возвращает ту же форму ответа, что регистрация; неверная пара email/пароль возвращает `401 Unauthorized`.

## Профиль

### `GET /api/profile`

Возвращает `{"user": User}` для владельца токена.

### `PATCH /api/profile`

Запрос:

```json
{
  "displayName": "Имя",
  "handle": "@nickname",
  "bio": "Интересы и предпочтения оформления"
}
```

Имя и никнейм обязательны; `@` добавляется сервером, если его нет. `bio` ограничен 500 символами. Ответ содержит обновлённый `user`.

## Записи

### `POST /api/days`

Требуются текст длиной 10–4000 символов, фотография и трек либо `songQuery`.

Нативный клиент отправляет `multipart/form-data`:

- `text` — текст записи;
- `track` — JSON-строка с объектом трека (или `songQuery` для поиска первого трека с preview);
- `photo` — обложка;
- `photos` — дополнительные изображения;
- `allowCloudAI` — `"true"` при явном согласии на вызов Gemini (по умолчанию `false`).

Сервер принимает до шести проверенных изображений (JPEG, PNG, WebP или HEIC), не более 15 MiB на файл; общий лимит тела HTTP-запроса — 95 MiB. Успешный ответ `201 Created` имеет вид `{"day": Day}`.

Также принимается JSON, например:

```json
{
  "text": "Длинная заметка о событиях, свете и ощущениях дня.",
  "photoUri": "https://example.com/photo.jpg",
  "photoUris": ["https://example.com/photo.jpg"],
  "track": {
    "id": 123,
    "title": "Название",
    "artist": "Исполнитель",
    "previewUrl": "https://example.com/preview",
    "genre": "Jazz",
    "artworkUrl": "https://example.com/artwork",
    "trackUrl": "https://example.com/track",
    "energy": 0.35
  }
}
```

Для JSON требуется `photoUri` или `photoUris`; это внешние ссылки, JSON-запрос не загружает файлы и не может ссылаться на серверные `/uploads`/`/api/media`. Если вместо объекта `track` передан непустой `songQuery`, backend ищет первый трек с доступным preview.

Необязательное поле `allowCloudAI` по умолчанию равно `false`. Только при `true` backend может отправить в Google Gemini текст записи, имя и описание профиля, заголовки последних пяти дней и данные трека. Файлы фотографий не отправляются; их цвета вычисляются локально на сервере.

### `GET /api/days`

Возвращает все записи текущего пользователя в порядке от новых к старым:

```json
{ "days": [] }
```

Необязательные query-параметры:

- `mood` — точное сравнение с категорией настроения, без учёта регистра; пустое значение или `all` не фильтрует.
- `q` — поиск подстроки без учёта регистра по названию папки, тексту, дате и полям трека, а также метке настроения.

Сервер сначала читает записи пользователя, а затем применяет эти фильтры в памяти. Клиентское приложение сейчас загружает весь архив и фильтрует его на устройстве.

### `GET /api/days/{id}`

Возвращает `{"day": Day}`. Запись другого пользователя считается не найденной и возвращает `404`.

### `DELETE /api/days/{id}`

Удаляет запись текущего пользователя и удаляет принадлежащие ей файлы, если они больше не используются другими записями. Возвращает `{"deleted":true}`; при частичной ошибке очистки добавляет поле `warning`.

### `GET /api/backup`

Скачивает ZIP-архив текущего пользователя: `manifest.json` с профилем и записями плюс доступные загруженные фото в `media/`. Лимиты — 5000 записей и 100 MiB фотографий. Если ранее загруженный файл отсутствует, запись остаётся в manifest, а предупреждение перечисляется в `warnings`. Для резервных копий PostgreSQL и тома Railway используйте также штатные средства платформы: этот endpoint не создаёт автоматические или плановые копии.

## Музыка и медиа

### `GET /api/tracks/search?q=<запрос>`

Требует JWT; `q` должен содержать не менее двух символов. Backend запрашивает iTunes Search API (магазин US), отбрасывает результаты без `previewUrl` и возвращает до 10 элементов в `{"tracks":[...]}`. При ошибке внешнего сервиса возвращается `502`.

Временные ошибки внешнего сервиса (включая `429` и `5xx`) повторяются ограниченное число раз с учётом `Retry-After`; если сервис всё ещё недоступен, API возвращает `503`.

### `GET /api/media/{owner}/{filename}`

Получает фотографию по 24-часовой HMAC-подписанной ссылке, которую сервер возвращает вместе с записью. Подпись привязана к владельцу; backend дополнительно проверяет, что запись этого пользователя ссылается на файл. Прямая статика `/uploads` отключена.

## Основные статусы

| Статус | Значение |
| --- | --- |
| `200` | Чтение или изменение завершено |
| `201` | Аккаунт или запись созданы |
| `400` | Некорректный JSON или не выполнена проверка входных данных |
| `401` | Отсутствует, некорректен или истёк токен; либо неверный пароль |
| `404` | Профиль или запись не найдены |
| `409` | Email уже зарегистрирован |
| `413` | Превышен лимит размера файла, тела запроса или резервной копии |
| `422` | Не удалось разрешить трек при создании записи |
| `502` | Не удалось выполнить поиск треков во внешнем API |
| `503` | Временная недоступность PostgreSQL или внешнего сервиса |
