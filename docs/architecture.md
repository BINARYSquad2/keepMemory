# Архитектура

KeepMemory состоит из клиента Expo и REST API на Go. Backend владеет аккаунтами, записями и рецептами стиля; изображения хранятся отдельно от PostgreSQL в локальном файловом каталоге.

## Компоненты

### Клиент `mobile/`

- Expo Router определяет экраны архива, создания записи, профиля, гида, авторизации и просмотра воспоминания.
- `services/api.ts` содержит HTTP-клиент, JWT, выбор базового URL, отправку альбомов и разрешение ссылок на медиа.
- `services/atmosphereInterpreter.ts` строит понятное объяснение оформления для архива и деталей, если backend не вернул готовые тексты.
- `MemoryCanvas.tsx` реализует карточку для нативной платформы, а `MemoryCanvas.web.tsx` — отдельный веб-вариант.
- Токен хранится в SecureStore на iOS/Android и в `localStorage` в браузере.

### Backend `backend/`

- Fiber регистрирует API, ограниченный CORS, liveness/readiness и защищённую выдачу медиа по подписанным ссылкам.
- `auth.go` реализует регистрацию, вход, хеширование паролей bcrypt и проверку JWT.
- `days.go` создаёт, перечисляет и читает записи, принимает фотографии в multipart-запросе и строит данные для сохранения.
- `tracks.go` обращается к iTunes Search API и нормализует результаты.
- `ai.go` формирует рецепт оформления: локально анализирует палитру первого загруженного фото, затем при наличии API-ключа запрашивает Gemini. При ошибке Gemini используется локальный рецепт.
- `db.go` подключается к PostgreSQL, создаёт таблицы `users` и `days` и декодирует JSONB-поля.

## Поток создания записи

1. Клиент проверяет наличие текста, хотя бы одной фотографии и выбранного трека.
2. Поиск трека выполняется через защищённый `GET /api/tracks/search`; клиент показывает результаты с доступным preview.
3. Приложение отправляет текст, сериализованный трек и файлы изображений в `POST /api/days` как `multipart/form-data`. JSON-вариант принимает внешние URI, но не позволяет подставить внутренний путь к чужому серверному файлу.
4. Backend проверяет формат и размер файлов, сохраняет их в каталог пользователя внутри `UPLOADS_DIR` и формирует для API-ответа временные подписанные ссылки.
5. Backend рассчитывает рецепт стиля по записи, треку, профилю, последним пяти воспоминаниям и цветам обложки. Gemini вызывается только при настроенном `GEMINI_API_KEY` и явном согласии пользователя для этой записи; бинарное фото не отправляется.
6. Запись и рецепт сохраняются в PostgreSQL. В ответ клиент получает объект `day` и открывает `/memory/<id>`.
7. Архив получает записи через `GET /api/days`, группирует их по неделям и выполняет поиск и mood-фильтрацию в интерфейсе. Экран деталей получает запись отдельно через `GET /api/days/{id}`.

## Маршруты приложения

| Экран | Путь Expo Router | Назначение |
| --- | --- | --- |
| Архив | `/` или `/(tabs)` | Список, поиск, настроение и недели |
| Новая запись | `/(tabs)/create` | Текст, альбом и выбор песни |
| Профиль | `/(tabs)/profile` | Данные пользователя, вход и выход |
| Гид | `/guide` | Описание этапов и визуальных режимов |
| Воспоминание | `/memory/[id]` | Карточка, альбом, песня, анализ и экспорт |
| Вход | `/auth/login` | Авторизация |
| Регистрация | `/auth/register` | Создание аккаунта |

## Внешние сервисы

- iTunes Search API — поиск музыки и ссылки на preview/страницу трека.
- Google Gemini API — необязательная генерация названия и рецепта только с явным согласием. При отказе, таймауте или временной ошибке используются локальные правила.
- PostgreSQL — постоянное хранение профилей и записей.
- iTunes и Gemini вызываются с ограниченными повторами для временных `429`/`5xx`; приложение повторяет только безопасные GET-запросы, но не повторяет создание записи автоматически.

Для Gemini отправляется текст дня, имя и bio пользователя, сводка заголовков последних пяти записей, данные трека, число фотографий и вычисленные цветовые значения. Бинарные данные фотографий в запрос Gemini не входят.

## Границы хранения медиа

`days` хранит пути к фото, а не содержимое файлов. Backend требует короткоживущую HMAC-подпись для выдачи изображения и сверяет владельца с записью; старые значения `/uploads/...` поддерживаются без миграции, но теперь тоже обслуживаются через защищённый маршрут. На Railway необходимо подключить постоянный Volume и указать `UPLOADS_DIR` на его mount path. Ручной экспорт данных доступен через `GET /api/backup`, удаление записи — через `DELETE /api/days/{id}`. Подробнее — [модель данных](data-model.md).
