# Настройка и запуск

## Требования

- Go версии, удовлетворяющей директиве `go` в `backend/go.mod`.
- Node.js и npm.
- PostgreSQL.
- Для разработки мобильной части — Expo CLI через локальный `npx expo`; Android/iOS инструменты нужны для нативных эмуляторов и сборок.

## PostgreSQL

Создайте базу данных заранее, например из `psql`:

```sql
CREATE DATABASE keepmemory;
```

## Переменные backend

Создайте `backend/.env` (или передайте переменные окружения процессу):

| Переменная | Обязательность | Значение |
| --- | --- | --- |
| `DATABASE_URL` | Да | PostgreSQL DSN, например `postgres://postgres:<password>@127.0.0.1:5432/keepmemory?sslmode=disable` |
| `JWT_SECRET` | Да для входа/регистрации | Случайная длинная строка; нужен один и тот же секрет между перезапусками |
| `PORT` | Нет | Порт HTTP-сервера; по умолчанию `8080` |
| `GEMINI_API_KEY` | Нет | Даже при наличии ключа Gemini вызывается только после явного согласия в форме создания; иначе используется локальный анализ |
| `GEMINI_MODEL` | Нет | Имя модели Gemini; значение по умолчанию задаётся backend |
| `UPLOADS_DIR` | Нет | Каталог файлов; по умолчанию `uploads` относительно рабочей директории backend |
| `CORS_ALLOWED_ORIGINS` | Нет | Список разрешённых web-origin через запятую; по умолчанию localhost для разработки |

`godotenv.Load()` читает `.env` из текущей рабочей директории. Поэтому запускайте `go run .` и `go test ./...` из `backend/`, чтобы автоматически использовать `backend/.env`. Не публикуйте секреты и не вставляйте их в отчёты или issue.

## Запуск backend

В PowerShell:

```powershell
Set-Location C:\path\to\KeepMemory\backend
go run .
```

При старте backend несколько раз повторяет подключение к PostgreSQL при временном сбое, затем создаёт `users`, `days` и индекс, если они отсутствуют. Существующая схема не меняется этой доработкой. `/health` проверяет процесс, `/health/ready` дополнительно проверяет БД и предназначен для health check Railway.

## Запуск мобильного/веб-клиента

В отдельном терминале:

```powershell
Set-Location C:\path\to\KeepMemory\mobile
npm ci
npx expo start
```

URL API выбирается в таком порядке:

1. `EXPO_PUBLIC_API_URL`, если задана;
2. Android: `http://10.0.2.2:8080`;
3. iOS Simulator и веб: `http://localhost:8080`.

Для физического телефона задайте IP компьютера в локальной сети до старта Expo:

```powershell
$env:EXPO_PUBLIC_API_URL = "http://192.168.1.10:8080"
npx expo start
```

Телефон и компьютер должны быть в одной сети; порт backend должен быть доступен через брандмауэр. Если URL меняется после старта Metro, перезапустите Expo, чтобы клиент подхватил переменную.

## Проверки

Из `backend/`:

```powershell
go test ./...
```

`TestAuthenticatedDayWorkflow` использует PostgreSQL и пропускается, если `DATABASE_URL` не задан. Когда база настроена, тест создаёт тестовые аккаунты/записи и очищает их.

Из `mobile/`:

```powershell
npx tsc --noEmit
```

В `mobile/package.json` нет отдельного скрипта lint/test. Запуск проекта выполняется через `npx expo start`.

## Эксплуатационные примечания

- Для Gemini оставьте `GEMINI_API_KEY` пустым, чтобы запускаться без внешней генерации.
- Наличие ключа не отправляет пользовательские данные автоматически: согласие на Gemini запрашивается отдельно при создании каждого воспоминания.
- Медиа выдаются только по подписанным ссылкам, ограниченным конкретным владельцем и сроком 24 часа. Не копируйте подписи в логи или публичные отчёты.
- Файлы лежат отдельно от БД. Настройте постоянный диск/том и задайте его mount path через `UPLOADS_DIR`; `/uploads` больше не является публичным статическим маршрутом.
- Перед публикацией явно задайте `CORS_ALLOWED_ORIGINS` для web-домена. Нативное приложение не использует CORS.
- `GET /api/backup` позволяет пользователю вручную скачать ZIP до 100 MiB, но не делает автоматические копии. Включите отдельные резервные копии PostgreSQL и постоянного тома в настройках хостинга.

## Развёртывание backend на Railway

1. Создайте Railway service из репозитория и укажите **Root Directory** `backend`, чтобы платформа обнаружила `go.mod`.
2. Подключите PostgreSQL и задайте `DATABASE_URL` значением внутренней переменной подключения Railway. Не переносите локальный `.env` в Git.
3. Сгенерируйте случайный `JWT_SECRET` длиной не менее 32 байт и задайте его в Variables. Сохраняйте это значение между релизами: замена аннулирует действующие токены.
4. Добавьте Railway Volume, смонтируйте его в `/data` и задайте `UPLOADS_DIR=/data/uploads`. Без постоянного тома загруженные фото могут исчезнуть при пересоздании сервиса.
5. Установите health check path `/health/ready`. Railway задаёт `PORT`; приложение слушает его автоматически.
6. Если включён web-клиент, задайте `CORS_ALLOWED_ORIGINS` точным origin сайта (например, `https://app.example.com`). Нативный клиенту CORS не нужен.
7. Включите штатные резервные копии PostgreSQL и тома. `GET /api/backup` — только ручной экспорт пользовательских данных.
8. После деплоя войдите в Expo/EAS, свяжите проект и добавьте публичный HTTPS URL сервиса как переменную `EXPO_PUBLIC_API_URL` в EAS environment `preview` через настройки проекта на expo.dev:

   ```powershell
   Set-Location C:\path\to\KeepMemory\mobile
   npx eas-cli login
   npx eas-cli init
   ```

   После настройки переменной соберите APK профилем `preview` из `mobile/eas.json`:

   ```powershell
   npx eas-cli build --platform android --profile preview
   ```

   Для локальной проверки можно задать `$env:EXPO_PUBLIC_API_URL` перед `npx expo start`. APK, собранный до настройки URL, продолжит обращаться к старому адресу. Перед сборкой проверьте идентификатор приложения `com.keepmemory.app`.

Railway-аккаунт, база, Volume, секреты и домен должны быть доступны владельцу проекта; наличие конфигурации в репозитории само по себе не публикует сервис и не создаёт облачные ресурсы.
