# Визуальная система

Каждое воспоминание получает рецепт из трёх цветов, художественного режима, варианта типографики, зернистости, скорости движения и текстовых пояснений. Клиент применяет рецепт к карточке с фотографией и альбомом.

## Художественные режимы

Идентификаторы и названия задаются в `mobile/constants/artStyles.ts`.

| Идентификатор | Название | Основной приём |
| --- | --- | --- |
| `analog_film` | Аналоговая плёнка | Тёплая фактура, зерно и камерная композиция |
| `minimal_editorial` | Выставочная сетка | Воздух, асимметрия и собранная композиция |
| `dreamy_aura` | Свет и аура | Мягкие ореолы и рассеянный свет |
| `kinetic_zine` | Кинетика и ритм | Контраст, геометрия и динамика |

Типографика: `serif_editorial` для более личной подачи или `mono_archive` для графичной. Категории настроения для фильтров: `happy`, `warm`, `calm`, `energetic`, `sad`.

## Как строится рецепт

1. Backend выбирает локальный рецепт по тексту, жанру/энергии трека, bio и количеству кадров. Это гарантированный fallback, доступный без внешних API.
2. Для загруженных файлов сервер пытается декодировать первый кадр как JPEG или PNG, выборочно берёт пиксели и вычисляет тёмный фон, акцент и светлый текстовый цвет. При JSON-запросе с уже существующими URI локального файла у backend нет, поэтому палитра строится без анализа изображения.
3. Gemini вызывается только если настроен `GEMINI_API_KEY` и пользователь отдельно включил необязательное согласие для конкретной записи. Тогда модели передаются текст, имя и описание профиля, заголовки последних пяти дней, сведения о треке, число фотографий и вычисленные цвета. Фото не отправляется. Без согласия или при ошибке API используется локальный рецепт.
4. Backend проверяет значения режима, настроения, типографики и цветов, ограничивает числовые параметры и принимает название папки только при длине 3–7 слов. Иначе используется безопасное локальное название. `style.aiGenerated` показывает, был ли принят ответ Gemini.
5. `mobile/services/atmosphereInterpreter.ts` строит подпись, категорию и объяснение для UI из текста, палитры, стиля и музыки, если серверная запись не содержит подходящего текста.

Тексты подписи и пояснения — описательная визуальная интерпретация, не психологическая оценка.

## Музыка и движение

Трек содержит `energy` от 0 до 1. Backend задаёт значение на основе жанра для результатов iTunes; локальная генерация использует энергию для скорости движения. Клиент использует `previewUrl` для короткого фрагмента, а `trackUrl` может открыть страницу трека во внешнем приложении или браузере.

Для альбома первый кадр считается обложкой; остальные можно переставить, удалить или добавить до шести. На карточке кадры сменяются при воспроизведении, а пользователь также может выбирать их вручную. Полная песня не загружается и не хранится приложением.

## Отрисовка и экспорт

- Нативная карточка реализована в `mobile/components/MemoryCanvas.tsx` с React Native Skia и анимацией.
- Веб использует отдельный `MemoryCanvas.web.tsx`.
- Экран воспоминания может озвучить текст и кураторское описание через системный TTS `expo-speech`; аудио синтезируется на устройстве.
- Экспорт оборачивает карточку в PNG через `react-native-view-shot`, затем открывает системное меню через `expo-sharing`.
- Экспорт поддерживается приложением iOS/Android; в браузере интерфейс объясняет, что сохранение PNG недоступно.

Основные цвета интерфейса и шрифты платформы находятся в `mobile/constants/theme.ts`.
